# 매달 하는 제도 점검

매달 1일 아침(한국시간)에 자동으로 실행된다. 이 문서가 그때 할 일의 전부다.

목적은 하나다. **화면에 떠 있는 숫자가 오늘도 맞는가.**
이 사이트는 "계산 과정과 근거를 같이 보여준다"를 이유로 존재한다.
근거가 낡으면 계산이 맞아도 틀린 답이 된다.

---

## 절대 어기지 않는 것

1. **확인하지 않은 숫자를 룰 파일에 넣지 않는다.**
   블로그·카페·SNS·유튜브 요약은 근거가 아니다. 법령 원문, 부처 보도자료,
   공공기관 공식 안내만 근거로 쓴다. 언론 보도는 그 원문을 찾는 실마리로만 쓴다.

2. **확정되지 않은 것은 룰 파일에 넣지 않는다.**
   예산안·입법예고·"추진 예정"은 전부 `rules/2026/pending-reforms.json` 쪽이다.
   국회를 통과했거나 관보에 실린 뒤에야 정식 룰 파일로 옮긴다.
   이 경계가 무너지면 사이트가 존재할 이유가 없어진다.

3. **확신이 없으면 바꾸지 말고 사용자에게 묻는다.**
   애매한 채로 고치는 것보다 그대로 두고 보고하는 편이 낫다.

4. **프로필 데이터를 서버로 보내는 코드를 쓰지 않는다.** (이 점검과 무관하지만 상시 금지)

## 순서

### 1. 무엇이 낡았는지 먼저 본다

```bash
python3 - <<'PY'
import json, glob
from datetime import date
today = date.today().isoformat()
for f in sorted(glob.glob('rules/*/*.json')):
    m = json.load(open(f, encoding='utf-8'))['meta']
    print(f"{m['ruleId']:<26} 확인 {m['verifiedAt']}  적용 {m['effectiveFrom']}")
PY
```

`verifiedAt`이 6개월(`STALE_AFTER_MONTHS`)을 넘긴 룰은 화면에 "기준값 확인 필요" 배지가
이미 떠 있다. **그것부터 확인한다.**

### 2. 달마다 정해진 확인 항목

| 시기 | 확인할 것 |
|---|---|
| 매달 | 지난 한 달 사이 시행된 법령 개정, 부처 보도자료 |
| 1월 | 최저임금 시행(실업급여 하한액이 따라 바뀐다), 새해 예산 확정분, 건강보험료율 |
| 3월 | 연말정산 관련 개정 반영 여부 |
| 7월 | 국민연금 기준소득월액 상·하한 조정(매년 7월), 육아휴직 관련 시행령 개정이 잦다 |
| 9월 | 다음 해 예산안 발표(`pending-reforms.json` 갱신) |
| 12월 | 국회 예산·세법 확정 → `pending-reforms.json`의 항목을 정식 룰로 옮길지 판단 |

### 4. 바뀐 게 있으면

- **금액·요율만 바뀐 경우**: 새 `effectiveFrom`으로 **새 룰 파일을 추가**한다.
  기존 파일을 덮어쓰지 않는다. 과거에 아이를 낳은 사람이 그때 기준을 봐야 하기 때문이다.
  `lib/rules/loader.ts`의 `REGISTRY` 배열에 추가하면 계산 로직은 손대지 않아도 된다.
- **제도 구조가 바뀐 경우**: 계산기 로직과 테스트까지 함께 고친다.
- **아직 확정 전인 경우**: `rules/2026/pending-reforms.json`에만 반영한다.
- 무엇을 고치든 `verifiedAt`을 오늘 날짜로, `verifiedBy`에 무엇을 보고 확인했는지 적는다.
- 설명 글(`content/`)에 그 숫자가 인용돼 있으면 **글도 같이 고친다.**
  `grep -rn "찾을숫자" content/` 로 확인한다.
